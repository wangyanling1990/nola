# Code Review 中文版

## When To Use

当用户要求审查代码、文档、架构、测试或实施计划时，使用此 Skill。采用审查姿态：先列问题，并按严重程度排序。

## Workflow

1. 阅读 `AGENTS.md` 和与被审查变更相关的文档。
2. 识别预期范围和阶段。
3. 检查正确性、回归、数据安全、可访问性、ADHD 友好 UX 和阶段漂移。
4. 如有可用测试或证据，进行验证。
5. 尽可能用文件和行号报告可操作问题。
6. 除非用户要求修复，否则审查期间不要改写工作。

## Required Output

- 按严重程度排序的问题
- 可用时提供文件和行号
- 开放问题或假设
- 测试缺口或剩余风险
- 只有在问题之后，才给简短变更摘要

## Quality Bar

- 问题具体且可操作。
- 审查保护 Nola 的温柔产品原则。
- 审查能发现意外扩展到移动端、同步、AI 或脚手架的情况。
- 若无问题，应明确说明并列出剩余风险。
