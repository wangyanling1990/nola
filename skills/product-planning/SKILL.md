# Product Planning

## When To Use

Use this skill when the request concerns product intent, user needs, MVP scope, roadmap tradeoffs, feature priority, acceptance criteria, or sprint planning for Nola.

## Workflow

1. Read `AGENTS.md`, `docs/prd.md`, `docs/roadmap.md`, `tasks/backlog.md`, and the active sprint file.
2. Preserve Nola’s product promise: no pressure, gentle starting, ADHD-friendly recovery.
3. Separate phase 1 desktop MVP from later mobile, sync, and AI work.
4. Turn vague ideas into user outcomes, scope, non-scope, and acceptance criteria.
5. Add or update backlog and sprint items when product work becomes actionable.
6. Do not write business code unless the user explicitly asks for implementation.

## Required Output

- Product decision or recommendation
- In-scope and out-of-scope boundaries
- Acceptance criteria
- Backlog or sprint updates needed
- Open questions and assumptions

## Quality Bar

- The plan protects ADHD-friendly principles.
- The recommendation keeps desktop MVP focused.
- Future mobile, sync, or AI work is not pulled into phase 1 accidentally.
- Every proposed task has a clear user outcome.
