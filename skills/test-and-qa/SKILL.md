# Test And QA

## When To Use

Use this skill when the request involves quality strategy, test design, verification commands, regression coverage, QA scenarios, accessibility, release evidence, or checking whether work is complete.

## Workflow

1. Read `AGENTS.md`, `docs/testing-strategy.md`, `docs/design-system.md`, and the relevant task.
2. Match test depth to risk and change type.
3. For documentation-only work, verify file structure, Skill metadata, and absence of business code.
4. For future implementation, cover shared logic, SQLite persistence, reminders, UI flows, and accessibility.
5. Include ADHD-friendly QA: low pressure, clear next action, visual calm, forgiving recovery.
6. Do not claim success without fresh command output or concrete inspection.

## Required Output

- Test scenarios
- Commands or manual checks
- Expected results
- Actual evidence when available
- Risks or coverage gaps

## Quality Bar

- Verification is repeatable where possible.
- Manual QA checks are specific, not vague.
- Accessibility and ADHD-friendly experience are treated as required quality.
- Completion claims include evidence.
