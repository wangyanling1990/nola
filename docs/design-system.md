# Nola Design System

## Design Intent

Nola should feel soft, calm, and companion-like. The design must help users start without pressure.

Design sentence:

> 不催促，不评判，只轻轻拉你一把。

## Product Voice

Use:

- Gentle
- Concrete
- Short
- Encouraging
- Forgiving

Avoid:

- Shame
- Harsh deadlines
- Alarmist copy
- Dense productivity jargon
- Overly cheerful pressure

## Visual Principles

- Low stimulation before decoration.
- Clear hierarchy without visual shouting.
- Spacious layouts with predictable structure.
- Calm contrast that remains accessible.
- Stable controls that do not jump or resize unexpectedly.
- Soft but not childish.

## Token Direction

These are design directions, not final implementation tokens.

| Token area | Direction |
| --- | --- |
| Color | Warm neutral base, muted accent, accessible contrast |
| Typography | Highly readable, calm, no aggressive display styling |
| Spacing | Generous enough to reduce crowding |
| Radius | Soft but restrained |
| Motion | Minimal, purposeful, respect reduced motion |
| Shadows | Subtle and functional |

## Component Principles

| Component | Principle |
| --- | --- |
| Task item | Show title, state, and next action without clutter |
| Today view | Focus on what can start now |
| Inbox | Make capture easier than categorization |
| Random start | Present one gentle suggestion, not a command |
| Reminder | Nudge softly and allow dismissal |
| Calendar | Support orientation, not pressure |

## Interaction Principles

- Primary flows should be usable by keyboard.
- Buttons should use clear verbs.
- Empty states should offer a small next action.
- Overdue or unfinished states should not shame the user.
- Confirmation dialogs should be reserved for meaningful data loss.

## Accessibility Requirements

- Visible focus states
- Sufficient color contrast
- Screen-reader labels for controls
- No reliance on color alone
- Reduced-motion support
- Text that can fit without overlap at expected desktop sizes

## Review Checklist

- The screen feels calm within the first five seconds.
- A tired user can identify the next action.
- Copy does not blame or pressure the user.
- Important controls are visible and reachable.
- Layout remains stable when task titles are long.
