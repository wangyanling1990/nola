# Nola Design System 中文版

## 设计意图

Nola 应该感觉柔和、平静、像一个陪伴者。设计必须帮助用户在没有压力的情况下开始。

设计句：

> 不催促，不评判，只轻轻拉你一把。

## 产品语气

使用：

- 温柔
- 具体
- 简短
- 鼓励
- 宽容

避免：

- 羞耻感
- 严厉截止感
- 警报式文案
- 密集效率术语
- 过度兴奋式压力

## 视觉原则

- 低刺激优先于装饰。
- 层级清楚，但不要视觉喊叫。
- 空间充足，结构可预测。
- 对比度平静但仍可访问。
- 控件稳定，不应突然跳动或改变尺寸。
- 柔和但不幼稚。

## Token 方向

这些是设计方向，不是最终实现 tokens。

| Token 区域 | 方向 |
| --- | --- |
| 色彩 | 温暖中性色底、低饱和强调色、可访问对比度 |
| 字体 | 高可读、平静，不使用攻击性展示样式 |
| 间距 | 足够宽松，降低拥挤 |
| 圆角 | 柔和但克制 |
| 动效 | 最小、明确，并尊重减少动效偏好 |
| 阴影 | 轻微且功能性 |

## 组件原则

| 组件 | 原则 |
| --- | --- |
| 任务项 | 不拥挤地展示标题、状态和下一步 |
| 今日视图 | 聚焦现在可以开始的内容 |
| 灵感箱 | 捕捉应比分类更容易 |
| 随机启动 | 给出一个温柔建议，而不是命令 |
| 提醒 | 轻轻提醒，并允许忽略 |
| 日历 | 帮助定位，不制造压力 |

## 交互原则

- 主要流程应可通过键盘使用。
- 按钮使用清楚动词。
- 空状态提供一个小的下一步。
- 逾期或未完成状态不应羞辱用户。
- 确认弹窗只用于真正的数据损失风险。

## 可访问性要求

- 可见焦点状态
- 足够颜色对比度
- 控件有屏幕阅读器标签
- 不只依赖颜色表达信息
- 支持减少动效
- 文本在预期桌面尺寸下不溢出、不重叠

## 评审清单

- 屏幕在前五秒内感觉平静。
- 疲惫用户也能识别下一步。
- 文案不责备、不施压。
- 重要控件可见且可触达。
- 长任务标题下布局保持稳定。
